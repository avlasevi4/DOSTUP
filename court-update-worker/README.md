# Обработчик обновления сведений судов

Это Cloudflare Worker для сайта «Реестр дел». Он принимает только ссылки на
страницы `*.sudrf.ru`, последовательно читает таблицу «Движение дела» и отдаёт
будущие события «Судебное заседание».

По кнопке на сайте Worker по-прежнему только возвращает результат проверки:
карточки меняются лишь после подтверждения пользователя. Дополнительно Worker
запускается ежедневно в 07:30 и 13:00 по Москве, сверяет активные дела и записывает в
Firestore **только пакет ожидающих изменений**. Карточки судебного производства
автоматически не обновляются.

## Публикация

Нужен бесплатный аккаунт Cloudflare и установленный Node.js 20+.

```powershell
cd court-update-worker
npm install
npx wrangler login
npx wrangler secret put FIREBASE_API_KEY
npx wrangler deploy
```

Команда выведет адрес вида:

```
https://dostup-court-updater.<ваш-аккаунт>.workers.dev
```

Вставьте этот адрес в `../court-update-config.js` вместо пустой строки и
опубликуйте изменения на GitHub Pages. После этого кнопка «Обновить даты» на
сайте начнёт работать.

## Ограничения и безопасность

- Worker принимает запросы только с `https://avlasevi4.github.io`.
- Обрабатываются максимум 12 карточек за один запуск, по одной странице за раз.
- Разрешены только HTTPS-ссылки на поддомены `sudrf.ru`; это исключает доступ к
  произвольным сайтам или внутренним адресам.
- Заседания с уже заполненным результатом считаются состоявшимися и не попадают
  в предложение обновления.
- Ключ `FIREBASE_API_KEY` задаётся как секрет Cloudflare и не попадает в GitHub.
  Идентификатор проекта хранится в `wrangler.toml`; это не секрет.
- Планировщик Cloudflare использует UTC. Правило `30 4 * * *` соответствует
  07:30 и 13:00 по московскому времени (UTC+3).
- При успешной проверке без различий прежний пакет уведомления удаляется. Если
  страницы судов не ответили, прежние неприменённые предложения не стираются.
